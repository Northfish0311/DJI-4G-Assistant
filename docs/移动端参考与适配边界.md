# 移动端参考与适配边界

## 当前状态

本项目当前 Android 和 iOS 客户端通过局域网连接 Windows 助手，模块留在电脑上。
本轮界面调整仍是源码改动，未发布新安装包，也未完成新版本真机验证。
不能把其他项目声明的能力当成本项目已经支持。

## 已核对的通信实现

### CardDock：安卓模块直连参考

- 仓库：https://github.com/Godles-lab/usb-modem-sms
- 本轮代码快照：8fe736a1d95a7a2daaedbdc6b5d614b4679236d0。
- 文件：app/src/main/java/dev/usbsms/Modem.kt。
- 使用 Android USB Host API、后台 bulk 读写和互斥锁；逐接口探测 AT，支持延迟重试。
- 当前 findDevice 仍匹配常量 2CA3:4006，不能直接宣称覆盖已经改成 2C7C:0125 的设备。
- 接口探测不应无差别占用网卡、音频或诊断接口。我们的直连实现需要受支持设备和接口范围、超时、取消与释放机制，不能原样照搬强制 claim 所有成对端点接口的方式。
- 可借鉴的交互：底部常用导航、按号码聚合短信、未读状态、存储容量提示、设备状态常驻。

### NekokoLPA：跨平台 eSIM 参考

- 仓库：https://github.com/iebb/NekokoLPA
- 本轮代码快照：e3202fb233b006f197ca77c0c314c6d9538d91d5。
- 文件：ios/CCIDPlugin.swift。
- 通过 CryptoTokenKit 的 TKSmartCardSlotManager 枚举读卡器，使用 TKSmartCard 会话发送 APDU。
- 这是系统支持的智能卡读卡器路径，不是通用 USB bulk 或 AT 串口接口。
- 支持兼容读卡器不等于支持 DJI 模块直插；需要单独验证设备是否暴露受支持的接口。
- 可借鉴的结构：设备适配器与套餐界面分离，下载进度和错误有独立状态，连接断开后清除当前会话。

## 我们采用的产品原则

1. 远程管理和硬件直连分开标识，未实现的直连入口不伪装成可用功能。
2. Android 和 iOS 保持相同的功能名称，但尊重各自原生导航和权限规则。
3. 多 EID 只使用标准入口和已经适配的厂商入口；未知私有入口不猜、不自动切底层芯片，读不到明确显示“暂不支持”。
4. 一个 EID 下可有多个套餐；界面不能把 EID 数量、套餐数量和物理设备数量混为一谈。
5. 本地统计流量不冒充运营商剩余流量；没有运营商查询来源就显示无法查询。
6. 自动发现先只读；写卡、发短信、切 USB 模式需要明确操作和必要确认。
7. 复制或修改第三方源码之前核对对应版本和文件许可证，保留所需版权与许可声明。本轮仅记录研究结论，没有引入第三方源码。

## 下一步验证

- 安卓：受支持 USB 设备发现、用户授权、限定接口探测和拔插恢复，然后再测试短信和 APDU。
- iOS：远程版持续维护；读卡器能力与 DJI 直插能力分别评估，不能用模拟器通过替代硬件验证。
- 两端：小屏、大字体、深浅主题、键盘弹出、断线和权限拒绝都需要检查。
