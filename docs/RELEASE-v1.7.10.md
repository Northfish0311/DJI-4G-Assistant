# DJI 4G Assistant v1.7.10

## 下载与安装

普通用户下载 **DJI-4G-Assistant-Setup-1.7.10-x64.exe**，退出旧软件后安装，再打开桌面图标。保留当前设置和已校验语音文件。Portable 是免安装版；Source code 不是安装包。

## 实机声音通道修复

- 修复进程检查将 `--voice-route-session` 误认成命令选项，导致真实路由运行却未被正确确认的问题。
- 独立后台进程先登记自己的 PID 与启动时间，再启动可能触发 USB 重连的声音程序，避免登记中断。启动器等待真实程序接管后才退出，并明确忽略 ADB 退出时的挂断信号。
- 对旧版遗留的声音进程，只在本软件专用路径、精确启动参数和固定 SHA-256 均匹配时回收；不按通用进程名强制结束。多个匹配进程或校验异常时停止自动操作。
- 重建内部路由前先清理不完整的自有旧路由，避免 PCM 被占用。使用正常终止信号和声音回退，不发送 SIGKILL。
- 修复换卡或 USB 重连后通话能力被清空却未重新读取的问题；当前电话页自动刷新，拨打或接听前再次检查缺失的能力状态。旧卡延迟返回的能力和呼叫状态不覆盖新卡。
- 增加默认开启的“自动接入声音”开关。关闭时不自动打开麦克风或准备声音，仍可接通后手动启动声音，方便区分呼叫失败与声音接入失败；不修改卡与网络配置。
- 声音接入直接打开用户选定的实际电脑麦克风，不为权限探测误打开可能已成为默认设备的模块麦克风；同一麦克风流复用至通话结束，不反复关闭和重新采集。输出也核对实际设备，不依赖可变默认设备别名。
- 接通后先确认模块声音路由启动，再查询、采集 Windows 音频，避免等待仍处于关闭状态的 USB 声音设备。已能读取电脑麦克风名称时，不再为了权限探测重复打开和关闭采集流。
- 声音启动不再在已接通的电话中执行耗时的完整 Windows 设备扫描；仍先读取并严格验证当前 QDC507GLEFM21 固件与呼叫状态，随后通过实际 ADB 连接、匹配内核和实际音频采集验证接口。完整 Windows 驱动扫描保留在诊断和准备页面。
- 电话页面使用轻量 CLCC 状态轮询，来电显示设置在能力检查及明确操作时更新，避免每次查询都重复读取可选属性而拖慢声音接入。
- 窗口隐藏或最小化后，已有呼叫仍继续读取状态并按正常流程接入或释放声音；没有呼叫时仍暂停后台空闲轮询。

## 已验证与限制

在实际 QDC507GLEFM21、Linux 内核 3.18.44 上验证了临时驱动与校准加载、三个连续声音路由启停周期、USB 声音开关开启、收发 PCM 同时 RUNNING，以及停止后释放通道。未拨号、未发送短信、未播放测试音，不修改 APN、eSIM、USB 模式、运营商 MBN 或固件。

**真实双向通话和接通数秒后挂断问题仍需实际呼叫验证。** 数据联网、USB 声卡出现和声音路由自检通过，都不能证明套餐支持语音或运营商接受 IMS/VoLTE。仅有数据流量的套餐通常不能用于验证接打电话；软件不会自动猜测或修改套餐权限。

2026-10-06 的受控电信自动语音短测中，呼叫保持了二十多秒后由测试程序主动结束，已确认模块 8 kHz 下行有非零音频，Windows 麦克风与播放流建立成功。这只验证一个呼叫目标的链路，不代表私人号码通话、所有套餐或用户实际听感均已通过；不能用这次结果承诺自动挂断问题全面解决。串口控制线设置只做了有备份、未保存到 NVM 的临时对照试验，发布代码没有自动套用它。

继续使用固定版本的 [MaVo 语音运行时](https://github.com/moluncn/mavo/blob/0443dfdaf8aec086fd76ba2ee9152fd908114524/module/mavo_pcm_bridge.c)，未替换驱动二进制，仍逐个验证固定大小和 SHA-256。请只从本仓库下载；遇到 Edge / Windows 未签名提醒先核对来源和校验值，不要关闭系统安全保护。
