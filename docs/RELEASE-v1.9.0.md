先退出旧版。两个文件选一个即可，不需要安装 Node.js：
- [安装版（推荐）](https://github.com/Northfish0311/DJI-4G-Assistant/releases/download/v1.9.0/DJI-4G-Assistant-Setup-1.9.0-x64.exe)：双击安装，之后从开始菜单打开。
- [免安装版](https://github.com/Northfish0311/DJI-4G-Assistant/releases/download/v1.9.0/DJI-4G-Assistant-Portable-1.9.0-x64.exe)：双击直接运行。

## 这一版的主题是「不用等」

从 1.8.7 到此版本的这几周，改动集中在响应速度上；功能面没有大改，但原来要等的操作现在几乎立刻返回。

### 速度

| 操作 | 1.8.7 | 1.9.0 |
|---|---|---|
| 设备检查 | 约 11.3 秒 | **约 0.08 秒** |
| 网络页流量 | 约 9.7 秒 | **约 0.05 秒** |
| 网卡信息 | 约 0.3 秒 | **约 0.04 秒** |

原因不是换了界面框架，而是换掉了两个慢性子查询：`Get-PnpDevice`（逐台枚举整机设备，冷热态都要 10 秒以上）改为读 Windows 注册表；`pnputil /enum-devices` 改为 .NET 网卡接口判断。网卡页也不再调用 `Get-NetIPConfiguration`。

### 启动

- 没有 AT 端口时不再逐项扫描：短信和 eSIM 直接给出「没有可用的串口」提示，而不是先跑一轮再报错。
- 复用查找 AT 口时已经得到的端口快照，启动阶段不再重复探测。
- 模块未插时不枚举整机设备清单。

### 一并带来的修复（1.8.8–1.8.12 累计）

- 关掉窗口后整组进程真正退出，不再在后台残留。
- 短信索引从 0 开始的模块（本机联通模块就是）也能正常删除。
- 「优先使用 Wi-Fi」这类操作最多等 20 秒，不会再让按钮卡死。
- 页面与电脑端接口版本不一致时会直接提示，而不是某个按钮点了没反应。

## 仓库里的 Tauri 实验分支

`main` 现在包含 `lab/tauri/`（Rust 外壳 + 系统 WebView2 的实验构建）。**它不会进入本安装包**：打包白名单只有 `desktop/`、`web/` 和 `node_modules/`。实验版的体积、进程与内存数据见 `lab/tauri/README.md`，目前结论是启动快但进程和内存不占优，暂不作为正式分发方式。

## 验证边界

速度数据为本机实测（热态），单元测试 341 项在 CI 通过；**「电脑走 Wi-Fi 且收到新短信」的实机组合验证仍未完成**。模块的短信、eSIM、通话功能本次没有改动逻辑。

Edge 或 Windows 可能提示文件不常见。请只从本仓库下载，无需关闭安全防护；可用同一发布页的 `SHA256SUMS.txt` 对照下载文件的 SHA256。
